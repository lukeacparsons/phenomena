# Phenomena and VO Barna

The existing Phenomena page is `static/index.html`. VO Barna is the separate generated multi-cinema site; its interactive CSS and JavaScript are `static/cinemas.css` and `static/cinemas.js`. `static/cinemas.html` is the old development shell, available only in legacy preview mode. The wordmark uses the supplied Bungee font, served locally from `static/fonts/` alongside its SIL Open Font License.

The generated public site targets **https://vobarna.com**, with readable EN/ES/CA pages, persistent film and cinema URLs, source-linked profiles, metadata, sitemap and crawler routing. Run `npm run site:build`, then `npm run dev:public -- --no-background --port 8789`. See [public-site build, slug policy and launch instructions](docs/vobarna-publication.md) and the [SEO/GEO audit](docs/seo-geo-audit-2026-11-19.md). Pushing `main` deploys VO Barna through Coolify; see the [deployment and rollback guide](docs/vobarna-hetzner-deployment.md). The local collector and Cloudflare stale-cinema watchdog are configured; see the [crawler audit and operations guide](docs/crawler-robustness-audit.md).

The [visual system and component guide](docs/design-system.md) defines the shared flat styling, typography, poster sizing, modal behavior and page-wide audit. Run `npm run site:test:styles` against the public preview after changing shared presentation.

## Local preview

From this checkout, prepare the Python environment once:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r scripts/requirements-posters.txt
```

Fetch the complete published programme and cache the posters, then start the local server:

```sh
npm run preview:refresh
npm run dev
```

Open **http://127.0.0.1:8765/en/**. `npm run dev` builds and serves the public pages and URL policy by default; old `/cinemas.html?film=…` links redirect to their persistent film slugs. Opening a film dialog updates the address to that same readable path. Closing it restores the search, and reloading the film URL opens its complete static page. The server binds only to loopback. To use another port: `npm run dev -- --port 8766`.

For isolated debugging of the old shell, use `npm run dev:legacy -- --port 8766` and open `/cinemas.html`. That mode intentionally omits public pages and SEO routing; do not use it to assess launch readiness.

Seven cultural venues bring the directory to **38 entries**. Institut Français, CaixaForum Barcelona and La Casa Elizalde import verified original-audio screenings. CCCB/Xcèntric, Albareda and Can Carol have permanent programme links and monitored discovery lists, but no published showtimes until version evidence is verified. The catalogue includes future screenings with **verified original audio, in every room**. VOSE, VOSC, other original-language subtitled versions, and unsubtitled originals qualify. Spanish and Catalan originals qualify when the source explicitly identifies an original version or the screening audio matches a verified original language. The page offers a date bar and a single search for films, cinemas and format tags. Search terms combine on the same screening: for example, `Dune IMAX` or `Balmes Atmos`. Add **`big screens only`** to restrict results to the curated premium-room selection; it works alone or in searches such as `Balmes big screens only`. Rooms and formats appear on individual sessions, without additional filters. English, Spanish and Catalan interface labels are available.

The shared light/dark theme follows the device preference until a visitor uses the cinema curtain switch beside the language switch: closed curtains mean dark mode; open curtains reveal a sun for light mode. The dark site is rendered onto two textured Three.js cloth meshes over the flat light page. Opening pulls this fabric aside along smooth edges traced from the icon's frames; closing returns the same dark fabric along exactly the reverse path. The icon and page share a 750 ms clock, and pressing again reverses both immediately. Only the dark curtain surface folds and receives lighting; the revealed page stays undistorted. The choice persists across pages and browser tabs. `static/theme.js` restores it before styles paint; `static/theme.css` defines the palettes, including the inverted decorative background. The supplied animation is served from `static/cinema-curtain-toggle/`, with localized labels and keyboard focus support. Reduced motion skips the animation. If WebGL or a prepared viewport texture is unavailable, the theme switches directly. Textures are prepared before interaction and refreshed after content, scroll, or size changes; Three.js and html-to-image are served locally with their licenses. The texture uses native browser text layout, embedded fonts, and a pinned copy of the sticky header to preserve alignment when scrolled. Only visible content is captured; collapsed disclosures are omitted and offscreen blocks retain their layout boxes. Presses update the shared clock immediately; GPU drawing runs once per display frame. Folded poses are warmed before the first press. Capture work yields to input and is cancelled on a press, while GPU vertex shaders animate the folds. The switch is installed before 3D preparation. The html-to-image copy preserves computed font sizes, handles font discovery across the capture iframe, and supports cooperative DOM cloning. A static curtain switch works while animation assets load or if they fail. Without JavaScript, pages still follow the device theme. The decorative background uses a lossless WebP compiled from the original SVG, avoiding expensive vector style recalculation and compositing on theme changes. After editing the SVG, regenerate it with `node scripts/render_cinema_background.cjs` (Chrome, Pillow and Playwright required; `PLAYWRIGHT_MODULE` can point to an existing installation).

The generated JSON records the current session count and per-source coverage. Movie grouping uses source identities, shared IMDb IDs and a short explicit reviewed mapping in the builder; it does not fuzzy-match titles. The original Dune, its later adaptations, and double bills remain separate. Sources without a verified shared film identity may retain separate entries. Film cards prefer verified portrait artwork within a 4:3–8:5 height-to-width range (at most 20% height variation at equal widths), then resolution. Smaller theatrical posters take precedence over landscape stills. Reviewed cinema artwork lives in `scripts/poster_sources.json`, and IMDb identity checks in `scripts/poster_identities.json`; both are retained across refreshes. Desktop cards use aligned 2:3 poster frames; the actual artwork fits uncropped inside each frame with consistent 6px corners. Mobile artwork retains its bounded height. See the [visual system](docs/design-system.md) for rendered sizes and responsive rules.

Programme scans also collect published admission prices from Mooby, Verdi/Verdi Park, Girona, Filmax, Texas, Filmoteca, the three nearby A1 cinemas, Institut Français, CaixaForum, Casa Elizalde and explicit Maldà listings, alongside Phenomena's existing prices. Named general admission, fare ranges and explicit free entry stay distinct; missing prices and booking fees remain unknown. Screening prices are stored internally and excluded from the frontend, public programme data and WebMCP. [Price coverage, evidence and limitations](docs/screening-prices.md).

Posters now use Pillow-generated WebP derivatives at 160, 320, 480, 640 and 960 pixels wide (never larger than the original), with a tiny inline preview. Visible images sharpen first; only a 240-pixel scroll buffer is prefetched, with at most four downloads at once. Save-data/2G uses one visible-only, 160-pixel download; 3G uses two, capped at 320 pixels. Where connection information is unavailable, viewport size and pixel density determine quality. Connection improvements and larger viewports trigger sharper variants. Failed downloads leave the preview visible and retry when the connection returns. Dimensions remain fixed during sharpening, and reduced-motion preferences disable the transition.

`npm run images:build` prepares an existing preview snapshot without fetching from providers. The preview server, programme/metadata refreshes and public build prepare images automatically. Derivatives live in the ignored `static/preview-data/images/` cache, have content-derived URLs and are served with immutable caching; originals remain untouched. Public HTML includes responsive, lazy-loaded images for visitors without JavaScript. The header uses `static/clint-logo.webp`, generated from `static/clint.png`. Run `npm run images:test:browser` against the local public preview (default port 8791, configurable with `VOBARNA_PUBLIC_URL`); it checks scrolling, connection upgrades, failure recovery, stable image dimensions, search/dialogs and no-JavaScript rendering. Set `PLAYWRIGHT_MODULE` as for the other browser checks.

The browser fetches `preview-data/programme.json`, a compact projection of the collector's `screenings.json`. It retains all film/search metadata, aliases, credits, release dates, ratings, evidence sources and screening fields used by the UI/WebMCP. Repeated per-session artwork, film descriptions and raw collector records stay in the original snapshot. Programme transactions refresh both files; public pages use the same projection at `/programme.json`, expanding repeated localized screening URLs in memory. `npm run programme:check` compares searches and WebMCP answers against the complete collected snapshot.

A first view fetches only what it shows. The first listing poster carries `srcset` and `sizes` in the HTML, so the browser's preload scanner requests its final size before any script or layout; its `sizes` divide by device pixel ratios above 2 to match the loader's cap, and the inline preview fills the box meanwhile. The rest of the first row keeps the 160-pixel start and the connection-aware loader. The theme switch starts as its single resting frame: the other fifteen frames, Three.js and the page capture load only after the `load` event, the first catalogue attempt (`window.vobarnaProgramme`) and an idle period, or immediately when the switch is hovered, focused or pressed. On Save-Data, 2G and 3G they load only on that interaction, so the first change there is direct. The catalogue request has no fixed deadline; it is abandoned only after 20 seconds without receiving data, and refreshes never overlap. PostHog starts after `load` and an idle period, with earlier events queued. The third-party WebMCP origin-trial script is `async`; only tool registration waits for it. The small-screen position of the header subtitle comes from the build and CSS (a second copy above the dates, with `has-programme-subtitle` on the root element), so the header does not move when scripts arrive. `npm run site:test:loading` checks this order against the local public preview (default port 8789, configurable with `VOBARNA_PUBLIC_URL`).

The local server gzip-compresses JSON, HTML, scripts, styles, SVG and fonts, with ETags and conditional requests. Restart an already-running preview server after changes to its Python code. Browser Network panels distinguish the decompressed **resource size** from the smaller **transferred size**; the latter measures the network cost. A November 19 snapshot's 5.8 MB collector file became a 2.55 MB browser catalogue transferring about 359 KB, with all search fields preserved.

Ticket links open the relevant cinema's booking page. Phenomena sessions link to their official event page. The local page has no payment or ticket-selection workflow. The original Phenomena page and production Worker remain unchanged.

## Data and seats

`scripts/build_cinema_preview.py` discovers all published dates and builds `static/preview-data/screenings.json`. Generated data, the image cache and `.venv` are ignored by Git. Re-run `npm run preview:refresh` to update the snapshot, then use **Reload listings** in the page. Reloading the page reads the last generated snapshot; it does not trigger a provider scrape. Each cinema refresh is isolated: a failed or invalid result retains that cinema’s previous listings and collection timestamp, while successful cinemas update.

Direct programme requests remain the first choice. Known provider browser checks can use a separately deployed authenticated Cloudflare reader, restricted to approved public programme/ticket-information URLs. This checkout is configured; another collector host needs the private, ignored `.crawler-secrets/provider-relay.json` configuration. See [provider repairs and reader operations](docs/provider-collection-repairs.md).

For a catalogue-only refresh that retains existing title/rating metadata without new enrichment lookups, run `.venv/bin/python scripts/build_cinema_preview.py --skip-enrichment`. The normal refresh also resolves film metadata and poster fallbacks. Verdi/Girona room identities are cached for 24 hours; Zumzeig version pages for six hours. Programme requests are refreshed on each run.

`npm run preview:nearby` refreshes just the nine nearby cinemas and six newly included cultural programmes. It validates and updates each cinema independently, preserves failed and untouched cinemas' sessions and timestamps, and retains existing film metadata. This also allows those additions to refresh when an unrelated city source is unavailable. The full refresh includes the same sources. Programme-only entries are explicitly marked in coverage.

Seat counts are collected automatically while the local server runs, with a **15-minute refresh interval**. Cards and film details show the cached counts without a click; the visible page polls the shared cache every 15 seconds and shows ages such as “3 mins ago.” The first run fills the cache in the background. Later starts reuse `static/preview-data/availability.json`; failed updates retain the last count and its original timestamp. Unknown counts stay unknown. Change the interval with `npm run dev -- --seat-refresh-minutes 30`.

Each chain is queried sequentially, with up to four chains running concurrently. Phenomena uses one bulk request; Cinesa reuses its anonymous token within a run. Repeated failures pause requests to that chain until the next interval. Browser visits never trigger cinema requests. The browser also keeps the last programme and seat snapshot locally, renders it immediately on repeat visits, and checks for updates in the background.

The collectors retain ordinary/accessibility/area counts separately. The UI shows only the seat total, with a relative refresh age inline in the modal. It labels closed bookings and zero ordinary seats as “Sold out.” Automatic adapters cover Phenomena, Mooby, Cinesa, Splau, Verdi/Verdi Park and Filmax. Filmoteca and Zumzeig carry timestamped counts from programme collection; these update with the catalogue. Yelmo, Girona, Renoir and Texas link to their ticket providers with unknown counts. Maldà links to its box-office programme. Splau's adapter follows an empty anonymous entry form without selecting tickets or seats. Restart the local server after changing adapters.

The builder uses public schedule requests and the existing Phenomena public data endpoint. The managed local service refreshes programmes hourly, seats every 15 minutes and metadata daily, and publishes a health heartbeat every five minutes. A Cloudflare watchdog checks every 15 minutes and sends stale/recovery alerts to the existing Telegram topic. The preview detects the managed service and reads its shared caches. See [crawler robustness and operations](docs/crawler-robustness-audit.md) for thresholds, tests and commands.

## Poster fallback

Schedule and daily metadata refreshes check verified cinema posters against the **600 × 900** minimum and a portrait width/height ratio of **0.60–0.82**, accepting both 2:3 and 4:5 theatrical artwork. Missing, undersized, square, landscape and unusually narrow images can be replaced by the matched IMDb film's poster. `scripts/poster_fallbacks.py` uses the independently resolved IMDb ID, an exact source ID, a reviewed mapping in `scripts/poster_identities.json`, or one unambiguous exact title-and-release-year match. Screening dates are never used as release years. Ambiguous matches, double bills and unmatched performances keep their cinema artwork and are listed for review.

The shared policy in `scripts/poster_policy.py` ranks suitable posters ahead of pixel area across collection, fallback and catalogue merges, so larger banners cannot replace valid portraits. Policy changes invalidate cached rejections. Images are decoded and measured before selection, never enlarged. For exceptionally large IMDb originals, the collector requests the same artwork at 1200px width from IMDb's image CDN and checks the returned pixels. Replacements keep their film identity, original image, source URL and acquisition time. Valid cached replacements are reused for seven days, and unresolved searches for one day. A failed refresh retains previous artwork; it cannot remove showtimes. The anonymous feed works locally without an API key but is not a documented availability guarantee.

Run `npm run preview:posters` to refresh fallback artwork without rescraping schedules, or add `-- --film imdb:tt42205124` to refresh one film while preserving other cached results. `static/preview-data/posters/fallbacks.json` records results and review candidates. Some event posters and unresolved titles remain below target.

The premium selection includes Balmes 8/9 + Atmos, Bosque 1 + Atmos, Aribau 5, Diagonal Mar IMAX/iSense, La Farga LUXE, La Maquinista PREMIUM/XE/Atmos, Splau Atmos/Laser ULTRA, and Phenomena. The new Yelmo venues use the same advertised PREMIUM/XE/Atmos rule; Barnasud requires an explicit IMAX/iSense attribute. “Big screens only” is shorthand for this selection, including comfort-focused venues.

## Film ratings

The modal shows Rotten Tomatoes' **critics' Tomatometer** and **audience Popcornmeter**, FilmAffinity's user rating and IMDb's user rating, each with an icon and a link to its source. RT icons follow its [60% threshold](https://www.rottentomatoes.com/about): a green splat for rotten critics' scores, a red tomato for fresh scores, and the corresponding full or tipped popcorn bucket for audiences. Unrated entries use gray icons and a dash. The audience value matches RT's displayed score (verified ratings when available, otherwise all audiences); it is collected from the same page request as the critics' score. Unresolved films link to the publisher's search instead of guessing a film page. Runtime remains in the header; the synopsis and cinema/screening counts are omitted.

The running local preview automatically refreshes ratings every 24 hours in a background thread, catches up on startup if they are stale, and retries failures hourly. The managed crawler or a preview with background collection must be running for this schedule to execute. `npm run preview:ratings` also refreshes ratings without rescraping schedules; the full `preview:refresh` runs this step too. Ratings are bundled into the programme JSON, so opening a modal makes no requests to rating providers. An open page checks the local programme every five minutes and when returning to the tab. `static/preview-data/ratings.json` retains source URLs, matching evidence, score counts and acquisition times. Failed requests keep an existing verified score with its original timestamp. Identity lookups are cached for a week. Background metadata writes preserve current schedules, posters and newly added films.

Film identities come from cinema IMDb IDs, verified poster identities and reviewed mappings in `scripts/rating_identities.json`. Wikidata links those exact IMDb IDs to Rotten Tomatoes and FilmAffinity identifiers; ambiguous mappings are rejected. Double bills and performances without a verified film identity remain unmatched. Ratings are read from each publisher's film-page structured data, and IMDb's [daily non-commercial dataset](https://developer.imdb.com/non-commercial-datasets/) is used for this local preview. No API keys are required. Icons are cached locally from the publishers' assets.

Missing original-language facts also come from the cinemas' own film pages. The collector reads explicit `Idioma original` and `Versión original en …` descriptions, preserves multiple languages, and separates subtitle phrases from audio. It checks the page's film title and available director/runtime evidence, records each source separately, and leaves existing publisher language data intact. This fallback works without an IMDb match when the catalogue already links to the exact film page. It never changes another venue's version or subtitles. Pages are cached for 24 hours; failed refreshes retain dated evidence. `npm run preview:languages` refreshes only this metadata while preserving screenings and ratings. The normal metadata refresh runs the same collector.

For language display, an explicit publisher **Original Language** field takes priority over an unranked Wikidata language list; verified cinema original-language fields can also replace that catalogue fallback. `details.language_selection` records the selected source, while `language_reports` retains the other reports without combining conflicting claims into the displayed original language. Explicitly multilingual originals retain their full list. Catalogue-only fallback values are labelled “Languages,” and regional publisher labels such as “British English” display as “English.” Superseded language aliases do not re-enter the original-language search data. Nationality, title language, subtitles and VOSE labels never establish a film's original language or change a screening's original-audio qualification.

`scripts/film_identity.py` runs **before ratings and artwork, even for films with good posters**. It gathers published original, English, Spanish and Catalan aliases using the [Wikidata entity API](https://www.mediawiki.org/wiki/Wikibase/API), IMDb suggestions and verified FilmAffinity pages. Renoir, Zumzeig and source-linked film detail pages supply labelled director, year, language and runtime evidence. A localized search result only nominates a candidate: matching also requires corroborating film facts, rejects conflicting versions/remakes, and leaves insufficient evidence unresolved. When needed, a verified FilmAffinity film's original/English titles, year and principal cast bridge to IMDb. Provider searches try published title variants and cache verified film URLs; they never machine-translate a title or attach a search result's score without checking its identity.

`static/preview-data/film-identities.json` records evidence, aliases, candidate IDs and unresolved cases independently of the poster cache. Complete identities are reused for a week; missing matches/provider links retry daily and request failures hourly. Exact provider URLs and IMDb IDs are reused for subsequent ratings/poster requests. No full IMDb title dump or additional credentials are needed. The display-title policy below remains independent of the titles used for database searches.

Cards and modals use verified original-language titles, with **English display titles for Asian-language originals**. Spanish and Catalan films keep their original titles in all three interface languages (EN, ES and CA); translated titles remain searchable aliases. Original, English and Spanish/cinema titles remain search aliases. Wikidata title statements and a small reviewed `scripts/film_metadata_overrides.json` provide canonical titles; missing English titles for Asian-language films can be resolved through IMDb's exact-ID suggestion feed. Poster and ratings lookups prefer verified IDs; text searches prefer English or original titles. The full refresh resolves these titles before poster fallback searches. Dune's 1984 and 2021 adaptations retain their year labels. A reviewed ID correction is allowed only for explicitly listed superseded source IDs; unrelated identity conflicts still fail closed.

Cross-cinema grouping runs during schedule assembly and after metadata refreshes. Verified film IDs take priority; case, accent and presentation-tag variants join only when title aliases are unambiguous and release years, directors and runtimes do not conflict. Bilingual headings join only when both names resolve to the same film. Editions and double bills stay separate. Merges preserve every session ID, booking link, format, availability record, search alias and the largest poster; former film IDs continue to resolve saved links. Renoir all-caps titles use the known original title when available, otherwise sentence case with reviewed proper-name exceptions in `scripts/source_title_overrides.json`.

## Film details and search

Interactive search prepares normalized film/session data once per programme snapshot, shares matching results between the date strip and cards, and redraws after a 60 ms typing pause on the next animation frame. It searches the entire catalogue while drawing cards in batches of 32, automatically adding more near the bottom or through the “Show more films” button. Unchanged cards retain their DOM and loaded posters. Programme replacement rebuilds the index; date expiry and seat observations are still checked against current state. Run `node scripts/test_search_browser.cjs` with `PLAYWRIGHT_MODULE` set when needed to check rapid typing, reset cancellation, text composition, reused cards and refresh behaviour against the public preview.

The initial HTML includes the date strip, search field and complete grouped showtimes, and starts the first four small poster downloads immediately. The builder invokes Node once to render all localized listings with the same `listing-view.js` module used in the browser. JavaScript adopts the existing cards, showtime links and decoded posters; unchanged cached/network responses do not rebuild them. The initial order remains stable through a showtime cutoff: passed sessions are marked and disabled in place, while the next explicit search/date action uses current-time ordering. Dialogs always exclude passed sessions. A separate image loader sharpens nearby posters before the catalogue arrives, using a 150 ms fade that respects reduced motion. Catalogue caching uses asynchronous IndexedDB, removes obsolete localStorage copies after a successful write, and falls back to localStorage when IndexedDB is unavailable. Cached and network reads run concurrently, and a late cache cannot replace fresh data. Availability uses ETag revalidation and the source refresh interval (normally 15 minutes), checks active refreshes every 30 seconds, retries failures after 60 seconds, and pauses polling while hidden. `node scripts/test_page_performance.cjs` checks visible controls, preserved cards/posters/showtime links, layout stability, early images, cache migration/offline search, restricted-storage fallback and conditional polling. `node scripts/test_loading_continuity.cjs` also crosses a showtime cutoff, verifies disabled past sessions, explicit reordering, identical-cache revalidation and metadata updates; it accepts the same `PLAYWRIGHT_MODULE` and `VOBARNA_PUBLIC_URL` settings as the other browser checks.

The same refresh collects directors, screenwriters, cast (including voice actors), genres, producers, composers, cinematographers, editors, production companies, countries, original languages, source material, runtime and release dates where published. `scripts/film_details.py` combines exact-ID Wikidata records with the verified Rotten Tomatoes and FilmAffinity pages. Publisher responses are shared with the ratings collector. Upcoming/recent titles refresh daily, older film facts weekly, and failures retain cached facts for hourly retries. `static/preview-data/film-details.json` records per-source facts, timestamps, status and coverage.

Credits and facts are searchable alongside titles, cinemas and screening formats, except producer-only credits. A person who also acts, directs or has another searchable role still matches that film. Searches ignore accents, match word prefixes and recognize genre aliases in English, Spanish and Catalan (for example, Sci-Fi / science fiction / ciencia ficción). Language and country searches recognize English, Spanish and Catalan names with or without accents: `Spanish`, `español`, `espanol` and `castellano` match Spanish audio or films produced in Spain; `Catalan` / `català` / `catala` and `French` / `francés` work the same way for their language or origin. Country names and nationalities (for example, `Francia` or `Mexican`) are searchable too. These aliases apply to existing cached metadata and known screening audio, including provider language codes. Subtitle labels and release territories do not add language or nationality aliases. Combine them with other terms, such as `French tomorrow` or `espanol IMAX`. Format terms still match the individual screening. A bare year searches film release years. Quoted dates search film metadata; unquoted ISO dates and date ranges select screening dates. The modal shows year, runtime, genres, director and original languages directly. The full collected credits and film facts remain in the data; producer-only names are excluded from search, including cached aliases; the expandable details section is omitted. Cards remain compact. Release dates retain their precision and territory; RT theatrical/streaming dates are labelled as US dates. Original source authors are distinguished from screenwriters. Events, double bills and films without verified identities are left unresolved instead of borrowing another title's credits.

Natural-language date search accepts today, tomorrow, weekdays, this/next week, weekends, this/next month, “in 2 weeks time”, “next 2 weeks” and ISO date ranges. Calendar calculations use Europe/Madrid: weeks run Monday–Sunday, a bare weekday means its next occurrence (including today), “in 2 weeks” is one date 14 days ahead, and “next 2 weeks” spans today plus the following 13 days. English, Spanish and Catalan phrases are supported. Combine dates with text, e.g. “comedy Saturday” or “Villeneuve next week”. Exact film titles and quoted phrases are protected from date parsing. Typing a date phrase clears an older date-picker selection; choosing a date button replaces the phrase and retains the rest of the search. Press `/` outside an editable field to focus and select the search; it also closes an open film modal.

## Browser agent tools (WebMCP)

The public-facing guide is [static/webmcp.html](static/webmcp.html), served at `/webmcp/` and linked from the screenings page footer and its HTML help link. It describes all six tools, inputs, workflows, returned data and current limits in static HTML that is readable without JavaScript. `/webmcp-tools.json` provides the exact tool descriptions, input schemas and annotations for agents; it is a documentation export, not an execution endpoint. Regenerate it after changing tool definitions with `npm run webmcp:docs`, or check for drift with `node scripts/export_webmcp_tools.mjs --check`. The reference points directly to `/webmcp/` and the three localized listings pages. The localized cinema pages also register these tools after their programme loads. Film detail pages and the WebMCP guide do not register tools. Public indexing depends on publishing the site at a crawlable URL.

VO Barna registers its six existing tools through `@nekuda/webmcp-sdk` after a valid programme loads. The EN/ES/CA homepages and localized cinema pages keep their existing registration coverage. Unsupported browsers and failed registration preserve the normal interface. Version 0.9.0 of the SDK is pinned in npm and its browser build is served as `static/webmcp-sdk.js`, with its license alongside it; upgrades must replace both from the pinned package. A plain Nekuda trial script runs before the application scripts. The SDK sends anonymous usage reports by default. The registration module also connects the six tools to the existing vobarna.com Production project in Nekuda; `.webmcp/connect.json` records that project and its dashboard links without credentials. Because these browser modules have no build-time environment substitution, the publishable connection setting is committed in `webmcp-registration.js`; every deployment of that code uses the same Production connection, restricted to https://vobarna.com. Unit registration tests replace the reporting transport so fixture calls never enter the account.

| Tool | Behaviour |
| --- | --- |
| `get_context` | Reads current filters, language, selected film/screening, cinemas, formats, collection coverage and freshness. |
| `search_screenings` | Searches upcoming sessions without changing the page; returns exact IDs, booking destinations, cached availability and a shareable search URL. |
| `get_film` | Returns collected film facts, credits and ratings, retaining source links and timestamps. |
| `get_screening` | Returns one session's time, room, format, availability and official booking link. |
| `set_search` | Replaces all visible filters, closes the dialog, updates the URL and returns the first 20 matching sessions. Empty arguments reset the search. |
| `show_screening` | Opens an upcoming session and highlights its ticket link. If the filters hide it, the dialog shows that film's upcoming sessions while the underlying search is preserved. |

`cinema-search.js` is the shared query implementation, `cinema-service.js` provides validated application operations and result serialization, `webmcp.js` keeps the schemas and existing handlers, and `webmcp-registration.js` owns SDK registration and MCP result wrapping. The four reads carry `readOnlyHint: true`; visible actions carry `false`. All results are marked as potentially containing external content. Runtime validation rejects unknown arguments, IDs, invalid dates and oversized inputs before changes occur. Cancellation is checked before execution; visible actions commit synchronously. Registration uses one lifecycle signal, rolls back a failed batch, and reads the latest programme/cache on each call.

Both search tools accept `query`, inclusive `date_from`/`date_to` bounds in Europe/Madrid, `cinema_ids`, `formats` and `big_screens_only`. Cinema IDs match **any** listed cinema; formats must **all** occur on the same session. Empty filters mean all upcoming collected sessions, independent of the current page search. Explicit dates override dates in the query. Natural date phrases use the same English/Spanish/Catalan parser as the UI. `search_screenings` also accepts `limit` (1–50, default 20) and `offset`; results are ordered by start time and screening ID and return `next_offset`. Registered tools return an MCP result: `structuredContent` holds the unchanged application result, and `content[0].text` is that same result serialized as JSON. `isError` is true when the application result has `ok: false`; the original error code and message remain in `structuredContent.error`. Consumers previously reading `result.ok` must read `result.structuredContent.ok` instead.

Structured filters appear as removable chips. URLs preserve them using `q`, `date` or `from`/`to`, repeated `cinemas` and `format` parameters, and `big=1`. Film and screening results use the persistent, localized URLs from the programme; screening links add a stable `#screening-…` anchor. Opening a dialog changes the address to that URL, and closing it restores the filtered listings URL. Sharing or reloading the URL opens the static film page at the screening row. Legacy `film` and `screening` query links redirect to these permanent paths; former film IDs remain supported after identity merges. Cinema booking URLs are preserved separately. The old development shell retains its query-based selection links.

Availability remains a cached observation, with `checked_at`, `age_seconds`, count `kind`, `stale`, provider support and refresh-failure flags. Staleness means the count is older than the configured collection interval. Ordinary seats, wheelchair/companion spaces where provided, and area counts retain their separate meanings. Missing prices/audio languages/counts stay unknown; VOSE does not imply English audio. The tools neither reserve seats nor perform checkout. Cinema/auditorium research remains outside this first release, as do time-of-day and rating-threshold filters.

For local native testing, enable `chrome://flags/#enable-webmcp-testing` in a supporting Chrome version and reload the page, or use a WebMCP-capable browser agent. Browser and agent support are separate; registering tools does not add an assistant UI. The current API can also be tested from the page console:

```js
const tools = await document.modelContext.getTools();
const search = tools.find(tool => tool.name === 'search_screenings');
const result = await document.modelContext.executeTool(search, { query: 'Villeneuve this weekend' });
const envelope = typeof result === 'string' ? JSON.parse(result) : result;
console.log(envelope.structuredContent);
```

With Playwright installed and Chrome available, run `npm run test:webmcp:browser` against the running preview. Set `PLAYWRIGHT_MODULE` to an installed Playwright module path if it is outside the project's dependencies; `VOBARNA_TEST_URL` overrides the default local URL and `BROWSER_EXECUTABLE` overrides Chrome. It never follows a cinema booking link.
